# Documentation updates

1. **Preserve value.** Before rewriting a page, classify its examples, syntax guidance, comparisons and caveats as valid, adaptable, incorrect or unverified. Keep valid material and adapt useful material to the current product. Explain substantive removals in the handoff. Clearly labeled cross-product comparisons can remain useful.
2. **Verify the reader's scenario.** Check the product and environment the page describes. For runtime claims, trace the full path and exercise a representative scenario where possible (for example, a static build for published output, not just the editor). Distinguish source inference, local tests and live deployment. If evidence is insufficient, retain the uncertainty rather than presenting an implementation detail as the feature's purpose.
3. **Check the result.** Verify affected links and examples when their targets or syntax change. Keep requested audit status clear: distinguish finished work from open or unverified items.
